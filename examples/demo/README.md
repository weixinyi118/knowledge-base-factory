# 示例库 · 自媒体内容

一套 20 篇正文 + 6 张速查卡的迷你知识库，用来演示 [knowledge-base-factory](../../README.md) 生成出来的库长什么样、写出来的内容长什么样。

骨架由 `init_kb.py` 生成（耗时 0.04 秒），内容按 `_内容标准` 逐篇写。**结构和字段与真实交付的库完全一致，只是篇数少。**

## 先说清楚一件事：这里的内容是示例

这不是一个可以直接拿去卖的自媒体课程库。它的作用有三个：

1. **让你看到成品形态** —— 总目录怎么组织、索引怎么带导航、卡和正文怎么互指。
2. **给你一个写作参照** —— 打开任意一篇，看开头是不是"具体的人 + 时间 + 数字"，看每个判断后面有没有挂证据。
3. **让你验证体检** —— 跑一遍 `python tools/check.py .`，P0/P1/P2 全 0，你可以故意改坏一处试试它能不能抓到。

**文中案例经过匿名化改写，数字是示意量级，不作为事实引用。** 每篇末尾的「来源与版权」都标了这一点。真要当资料用，请自己核实。

## 从哪开始

1. 打开 [`00_总目录.md`](00_总目录.md) —— 唯一入口，六个分类都从这可达。
2. 想看写作标准，读 [`_内容标准_去AI味与质检清单.md`](_内容标准_去AI味与质检清单.md)。
3. 想验证质量，跑 `python tools/check.py .`（需要 Python 3.8+，无第三方依赖）。

## 几条可走的浏览路径

- **只想看格式**：`00_总目录.md` → 任一 `_分类索引.md` → 挑一篇看开头两段。
- **想看"深度篇"和"标准篇"的区别**：对比 [`01_平台机制/01-三百播放的账号第五条跑到十二万.md`](01_平台机制/01-三百播放的账号第五条跑到十二万.md) 和 [`01_平台机制/02-完播率高不等于内容好.md`](01_平台机制/02-完播率高不等于内容好.md)。
- **想看卡和正文的关系**：读 [`速查卡/流量池五问.md`](速查卡/流量池五问.md)，再看它的 `parent` 指向哪篇。卡不是摘要，是"只剩 30 秒该记住什么"。
- **想看索引导航怎么写**：`01_平台机制/_分类索引.md` 里的「阅读导航（按目的）」——按"你现在的问题"排，不按逻辑顺序排。

## 数字

| 项目 | 数量 |
|---|---|
| 正文 | 20 篇（深度 4 / 标准 16），约 1.7 万字 |
| 速查卡 | 6 张，约 1300 字 |
| 分类 | 6 个（篇数 4/4/3/4/3/2，故意不均衡） |
| 体检 | P0 0 ｜ P1 0 ｜ P2 0 |

篇数不均衡是刻意的：平台机制和分发是这类账号最疼的两处，给了 4 篇；合规只有 2 篇，因为这部分写多了是凑数。真实交付时按主题厚度分配，不为了好看拉平。

## 约定

- 正文文件名 `NN-短名.md`，编号分类内连续、不复用。
- 每篇头部八个 YAML 字段，缺一不可；速查卡用另一套字段（无 `level`/`words`/`topic`）。
- 标准篇最多 2 个表格，深度篇最多 3 个。
- 每篇末尾标注来源与版权标签。

## 自己动手

```bash
# 从仓库根目录生成一个同样结构的新库
python scripts/init_kb.py ../我的知识库 --preset content

# 体检这个示例库
cd examples/demo && python tools/check.py .
```

`tools/` 里的两个脚本是 `init_kb.py` 复制进来的副本，最新版永远在仓库的 `scripts/` 目录。
