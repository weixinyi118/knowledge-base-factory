# 批量生产流程

150 篇不难写，难的是写到第 80 篇时风格还没散。这份文件管的是**节奏和质量控制**。

---

## 一、批次大小：8–12 篇

| 批量 | 会发生什么 |
|---|---|
| 1–3 篇 | 太慢，索引排不满，用户看不到体系感 |
| **8–12 篇** | **最优。一批能填满一个分类的可见区域，风格还没开始漂** |
| 15–25 篇 | 后半批开头开始雷同，判断变平，出现"正确的废话" |
| 30 篇以上 | 风格塌成模板，需要整批重写 |

**为什么是 8–12：** 上下文里堆太多自己刚写的产出，模型会向"平均值"收敛——所有篇目都变成同样的长度、同样的节奏、同样的开场。

---

## 二、单批的七步

```
1. 排选题表  → 写进 _分类索引.md 的表格（只写标题 + 一句话价值）
2. 写 3 篇   → 先写这 3 篇，回头看一眼质量
3. 校准      → 这 3 篇哪里不对？开场方式重复？判断太软？
4. 写完剩下  → 按校准后的手感写完本批
5. 更新索引  → 把篇目表填满，加「三篇先读」
6. 体检      → python tools/check.py .
7. 修         → P0 清零，P1 能修的修掉，再进下一批
```

**第 2–3 步不能省。** 直接写 12 篇，写完才发现开场全是"2023 年，一个……"，就得整批返工。

---

## 三、选题表怎么排（第 1 步）

在 `_分类索引.md` 里先写表，不写正文：

```markdown
| # | 标题 | 级别 | 一句话价值 |
|---|---|---|---|
| 01 | 一个人的三张表长什么样 | 深度 | 五行利润表、13 周现金流、四行资产负债 |
| 02 | 订阅还是买断 | 标准 | 稳态 MRR = 新增 MRR ÷ 月流失率 |
```

排表时检查三件事：

1. **有没有两个标题在讲同一件事？** 有就合并，或切成"上/下"两个不同角度。
2. **级别配比对不对？** 目标：深度篇 20–25%，其余标准篇。全是标准篇会显得浅。
3. **有没有硬货？** 每个标题后面的一句话价值里，有没有数字、公式、判据？没有的换掉。

## 四、风格不漂移的五个控制点

| 控制点 | 做法 |
|---|---|
| 开场方式 | 每批轮换 `references/content-standard.md` 里的 12 种，同一批不连用 |
| 句式 | 每 10 篇至少 2 篇用"对话 / 现场 / 一份文件"开头（不是数据型） |
| 长度 | 标准篇 900–1500，**不要每篇都写 1200**。900 和 1400 要混着来 |
| 判断强度 | 每批至少 2 篇有"敢得罪人"的句子，其余可以平一点 |
| 复盘 | 每完成 5 批，回头读第 1 批的一篇，比较语气。变了就校准 |

**漂移的典型信号：**

- 所有篇目都是"三段拆解 + 四条避坑 + 两条金句"的固定结构
- 开头全是年份 + 外国人名
- 每个判断后面都是"经验归纳"（说明没去查证据）
- 篇末的"来源与版权"写成同一句话

## 五、质检循环

```bash
python tools/check.py .          # 看报告
python tools/check.py . --fix    # 先自动修能修的
python tools/check.py .          # 复跑，确认 P0 = 0
```

**修的顺序：** P0（交付会坏）→ P1（影响可信度）→ P2（可解释就留）。

P0 里最常见的是 `category` 与目录不符。原因通常是复制模板时忘了改，`--fix` 能自动按目录名修正。

P1 里最常见的是 `companion` 指向空卡。**这个必须修**——用户点开会看到白页，以为是 bug。

P2 里 `words_off`（字数偏离）不用强修，但如果一批里有 5 篇都偏短，说明这批写得仓促，回头补证据。

## 六、排产参考

以 150 篇正文 + 50 张卡为例：

| 阶段 | 内容 | 批次 |
|---|---|---|
| 0 | 生成骨架、排全部分类选题表 | 1 |
| 1 | 重点分类（用户最关心的 2 个）各 12–15 篇 | 3 批 |
| 2 | 其余分类各 8–12 篇 | 5 批 |
| 3 | 速查卡（每批 10–15 张，配已完成的深度篇） | 3 批 |
| 4 | 全库体检 + 索引补齐 + 交付打包 | 1 |

**顺序原则：先写用户最关心的，不要从 01 顺序写起。** 万一中途停，交付时至少重点分类是满的。

## 七、四种常见失败

| 失败 | 症状 | 原因 | 修法 |
|---|---|---|---|
| 只写不改 | 越写越平，读起来像资料汇编 | 没做第 2–3 步的校准 | 停下来重读 3 篇，重写其中 1 篇找手感 |
| 一次写太多 | 第 20 篇开始所有篇目一个味道 | 批次太大 | 拆小批，中间插入体检 |
| 最后统一修 | 修完 A 又坏 B | 错误互相掩盖 | 每批修完再进下一批 |
| 索引不更新 | 目录里看不到新篇目 | 只写正文没回填索引 | 体检的 `index_unlisted` 会抓，别忽略 |

---

## 八、什么时候可以停

满足这三条就可以交付：

1. P0 = 0，P1 ≤ 3 且有明确理由
2. 每个分类 ≥ 8 篇（少于 8 篇的分类合并或删掉）
3. 随便抽 3 篇，开头都是具体事件，不是结论

**不需要等到"完美"。** 内容库是活的，交付后按用户反馈继续补比一次做到 100 分更实际。
