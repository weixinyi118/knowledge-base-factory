# knowledge-base-factory

**把一堆笔记变成一套可交付的知识库。骨架 3 秒，内容按标准逐篇生产。**

A production line for structured knowledge bases: scaffold in 3 seconds, content by a written standard, quality gated by scripts.

---

## 这玩意儿是怎么来的

它不是一个拍脑袋想出来的模板。

2026 年 10 月，我在给一个创业社区做会员知识库：8 个分类、150 篇正文、59 张速查卡、约 19.6 万字。写完自检时跑了几个脚本，抓出两个我自己完全没发现的问题：

- **93 篇的 `companion` 字段指向了不存在的速查卡。** 在 Obsidian 里点开是白页，在 APP 里是一个空链接。人眼浏览 150 篇，看不出这个。
- **44 张卡的 `category` 字段是空的。** CSV 导出来那一列全是空白，运营按分类筛选会直接漏掉这 44 张。

这两个错误都不是"写的时候不小心"，是**规模一上来，人就不可能自己保证一致性**。

所以这套东西的核心不是模板，是**模板 + 标准 + 会抓错的脚本**。三样缺一样都不成立。

---

## 3 秒是什么，不是什么

| ✅ 3 秒能给 | ❌ 3 秒给不了 |
|---|---|
| 分类骨架、总目录、分类索引 | 内容本身 |
| 写作标准（去 AI 味 + 质检清单） | 真实案例、数字、失败样本 |
| 元数据规范（八字段） | 行业判断 |
| 交付说明、验收单、篇目清单 | — |
| 库内自检工具 | — |

骨架负责**不会走歪**，内容负责**值得读**。

任何声称"3 秒搞定 200 篇"的工具，第一次用就会被拆穿。这里不这么讲。

## 快速开始

```bash
git clone https://github.com/<you>/knowledge-base-factory.git
cd knowledge-base-factory

# 生成骨架（约 0.04 秒）
python scripts/init_kb.py ../我的知识库 --name "我的知识库" --preset opc

# 或者自定义分类
python scripts/init_kb.py ../产品手册 \
  --categories "01_选型:怎么选|02_部署:怎么装|03_踩坑:装完报错|04_运维:怎么监控"

# 写完内容后体检
python scripts/check_kb.py ../我的知识库

# 出清单 + 打包
python scripts/export_kb.py ../我的知识库 --version v1
```

纯标准库，无依赖，Python 3.8+。Windows / macOS / Linux 都行。

### 预设分类

| 预设 | 分类 |
|---|---|
| `opc` | 一人公司商业思维、AI 工具、算力基建、自媒体 IP、出海、人脉协作、风险避坑、工作流效率 |
| `content` | 平台机制、选题结构、视觉呈现、增长分发、变现商单、账号合规 |
| `tech` | 语言基础、框架架构、数据存储、部署运维、性能优化、协作交付 |

完整必答问题清单在 [`references/taxonomy.md`](references/taxonomy.md)。

## 生成什么

```
我的知识库/
├── 00_总目录.md                    ← 唯一入口，所有分类可达
├── _内容标准_去AI味与质检清单.md    ← 生产标准，补内容前必读
├── _交付说明.md                     ← 字段映射（给开发）
├── _验收单.md                       ← 交付签字用
├── _篇目清单.csv                    ← 全库索引，Excel 直接开
├── _示例篇目.md                     ← 一篇合格样张
├── README.md
├── tools/
│   ├── check.py                     ← 13 项体检
│   └── export.py                    ← 导出 + 打包
├── 01_一人公司商业思维/_分类索引.md
├── 02_AI工具与Agent落地/_分类索引.md
├── ...
└── 速查卡/
```

**库自带体检工具。** 生成时把 `check.py` 和 `export.py` 复制进 `tools/`，clone 下来就能查，不用回头找这个仓库。

## 13 项体检，分三级

```
P0 必修   frontmatter 缺失 / 必填字段缺失 / level 非法 / category 与目录不符 / 双链断链
P1 应修   companion 指向空卡 / 禁用词 / 索引漏篇 / 孤儿卡 / 分类索引缺失
P2 建议   字数偏离级别区间 / 文件名不规范 / 表格过多 / 版权标签非法
```

有 P0 返回退出码 1，可以直接挂 CI。

```bash
python tools/check.py .            # 体检
python tools/check.py . --fix      # 自动修 category 错位、补缺失字段、删空 companion
python tools/check.py . --json     # 机器可读
```

它比人靠谱的地方：

- **双链**：150 篇里的 `[[...]]` 逐个解析，断一个就报
- **companion**：正文说的卡到底存不存在，脚本说了算
- **索引覆盖**：每篇是否出现在自己分类的索引表里
- **禁用词**：会区分「使用」和「提及」——被引号裹住、或前面有"不用/别用"的，算教人别这么写，不报警

## 写作标准

三条硬规矩，是这套东西真正的护城河：

1. **开头必须是「事」，不是「理」。** 一个具体的人、时间、数字。不许用结论开场。
2. **每个判断必须挂证据。** 数字 / 时间点 / 当事人原话 / 一次带代价的失败 / 可当场演算的算式，五选一。挂不上就删。
3. **每篇要有一个「敢得罪人」的判断。** 四平八稳的内容不产生认知增量，只产生阅读量。

配套的还有：12 种可轮换的开场方式、禁用词替换表、五种反常识句式、三种失败样本来源、写完的四关自查。

全文见 [`references/content-standard.md`](references/content-standard.md)。

批量生产的节奏控制（一批多少篇、风格怎么不漂、质检循环）见 [`references/production.md`](references/production.md)。

## 适合 / 不适合

**适合：**

- 给 APP、社群、内部团队做可检索的内容库（几十到几百篇）
- 把散落的笔记、收藏、草稿整理成有分类有索引的体系
- 内容团队需要一套统一的写作标准和验收标准
- 想用 Obsidian 但每次建库都在重新想目录结构

**不适合：**

- 一次性文档（写一份需求文档不需要知识库）
- 纯个人日记（不需要分类、索引、验收单）
- 内容还没想清楚就先要 200 篇（先答 `references/taxonomy.md` 里的必答问题）

## 一个提醒

这套东西的价值不在生成骨架那 0.04 秒，在**标准**和**体检**。

骨架你花十分钟也能手建。但如果没有"每个判断必须挂证据"这条，AI 会用一天时间给你写出 150 篇看起来很像、读起来全是正确废话的东西。如果没有体检脚本，你会带着 93 个看不见的坏链接交付出去。

**先读标准，再动手写。** 顺序反了，后面全是返工。
